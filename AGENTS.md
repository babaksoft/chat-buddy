# Repository Guidelines

## Project Structure and Architecture

Chat Buddy is a Python 3.12 local-first chat application: Streamlit drives application services, which use domain abstractions and infrastructure adapters for Ollama and PostgreSQL. Keep dependencies pointing inward:

- `src/chat_buddy/domain/` holds immutable domain models, exceptions, and `Protocol` interfaces.
- `src/chat_buddy/application/` holds use cases, schemas, context building, and services in `application/service/`.
- `src/chat_buddy/infrastructure/` implements database repositories, SQLAlchemy models, Ollama access, tokenization, configuration, and logging.
- `src/chat_buddy/ui/streamlit_app.py` composes dependencies in `build_services()`; keep UI code thin.
- `src/chat_buddy/prompts/` is the sole home for LLM prompt templates.
- `alembic/versions/` contains schema migrations; `tests/` mirrors application and infrastructure areas, with end-to-end coverage in `tests/integration/`.

Put business rules in services, persistence only in repositories, and external contracts in the domain layer. Do not issue direct SQLAlchemy queries from services or UI code.

## Setup, Running, and Database Changes

Use Python 3.12 and install dependencies with `pip install -c constraints.txt -e ".[dev]"`. Start PostgreSQL using `docker-compose up -d`, apply schema changes with `alembic upgrade head`, and run the UI with `streamlit run src/chat_buddy/ui/streamlit_app.py`. Ollama must be available at the endpoint configured in `infrastructure/config/settings.py`.

For a model change, add or update the SQLAlchemy model, repository, and a reviewed autogenerated migration: `alembic revision --autogenerate -m "add_feature"`. Never edit an applied migration.

## Style and Quality Checks

Use four-space indentation, complete type hints on every function, and Google-style docstrings when they clarify behavior. Name modules and functions in `snake_case`, classes in `PascalCase`, and tests as `test_<behavior>.py` with `test_<expected_behavior>()` cases. Prefer frozen, slotted dataclasses for immutable domain values.

Before committing, run the same checks as CI:

```bash
black --check src tests
isort --check-only src tests
ruff check src tests
mypy src tests
pytest -v
# or: scripts/check.sh
```

## Testing and Contributions

Add focused unit tests beside the affected layer; add an integration test when a change crosses service and repository boundaries. Use shared fixtures from `tests/conftest.py` and keep the full suite passing without requiring unstated local state.

Commit subjects in this repository are short, imperative, and scoped when useful (for example, `Add memory repository` or `Refactor context builder`). Keep each commit cohesive. Pull requests should explain the user-visible or architectural change, list validation run, link the relevant issue when one exists, and include Streamlit screenshots for UI changes. Call out migrations, model/configuration changes, and any required Ollama or database setup explicitly.
